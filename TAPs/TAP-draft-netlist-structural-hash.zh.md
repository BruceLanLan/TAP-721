# TAP-TBD：扁平网表的结构哈希

## 概要

本 TAP 扩展 TAP-721（网表绑定 NFT），为每份扁平 TapeOut 网表提供一个指纹：同一设计只是被重新编号、重新排序、填充了不用的门或被复制时，指纹保持不变，因此这样的副本无法冒充成不同的设计。

## 摘要

本 TAP 是 TAP-721（网表绑定 NFT，`TAP-draft-netlist-bound-nft`）的扩展：它为 TAP-721 代币的网表增加一个设计层面的标识符，不改动 TAP-721 本身的任何内容。网表文件（`tapnet/1`，由 `TAP-draft-netlist-bound-nft` 定义）按字节由其 SHA-256 哈希标识。同一个设计可以写成许多不同的文件：门可以换一种顺序编号，NAND 的两个输入可以交换，可以加入不用的门，也可以复制某个门。本 TAP 规定 `tapnet/1` 文件的一种确定性规范化：去掉不可能影响任何输出的元件，给每个剩余元件一个结构标签（无反馈的元件靠哈希，依赖 LATCH 反馈的元件靠迭代细化），合并标签相同的元件，再按固定的元件顺序把结果写成一个规范 `tapnet/1` 文件。`structuralHash` 是该规范文件在一个域标签下的 SHA-256。两份网表的结构哈希相同，当且仅当它们合并后的结构同构，且输入与输出的顺序相同。结构哈希不是逻辑等价测试：同一函数的两种不同实现有不同的结构哈希。本 TAP 附测试向量（包括 BNB Smart Chain 主网上的电路）与参考实现。第 2 版（§10）以保守扩展的方式把结构哈希推广到含 ROM 记录、ROM 读口和 RAM 端口的 `tapnet/2` 文件（`TAP-draft-large-netlists`）。

## 动机

`TAP-draft-netlist-bound-nft` 把每个代币绑定到一个网表文件，并按网表哈希统计版次。网表哈希随每个字节变化，所以它对设计什么也说明不了。一个宣传"10,000 个独一无二的电路"的集合，可以只用一个设计生成它们：给门重新编号、交换 NAND 输入、撒入不驱动任何东西的门，或者复制一个门并拆分它的扇出。这些改动每一项都会改变文件和网表哈希，却没有一项改变设计。持有人、交易市场和稀有度工具需要一个恰好忽略这些改写的标识符，这样"独一无二的设计"才可以核查，而不必轻信。

这个标识符必须定义得足够精确，使各个独立实现逐字节一致；必须足够便宜，能为大集合里的每个代币计算；还必须如实说明它检测不到什么。完整的逻辑等价不可行（见设计理由），而非正式的"重命名后相同"会让每个工具各用各的启发式方法。

## 规范

本文中的关键词 "MUST"、"MUST NOT"、"REQUIRED"、"SHALL"、"SHALL NOT"、"SHOULD"、"SHOULD NOT"、"RECOMMENDED"、"NOT RECOMMENDED"、"MAY" 与 "OPTIONAL"，当且仅当以全大写出现时，按 RFC 2119 与 RFC 8174 的描述解释。

### 1. 记号

| 记号 | 含义 |
|---|---|
| `‖` | 字节串拼接 |
| `u8(x)`、`u24(x)`、`u32be(x)` | 把 `x` 写成 1、3 或 4 字节的无符号大端整数 |
| `SHA-256` | FIPS 180-4 |
| `L(x)` | `SHA-256(ASCII("TAPSH1") ‖ x)`，一个 32 字节的**标签** |
| 标签上的 `min`、`max`、"升序" | 32 字节串的逐字节字典序（等价于按 256 位大端无符号整数比较） |
| 元件 | 文件中的一条记录；元件 `k`（从 0 起）产生信号 `2 + nIn + k`（TAP-02 §2） |
| `S` | `2 + nIn + E`，其中 `E` 为元件数 |

标签只作为字节串比较和哈希。实现 MUST 把两个相等的标签视为表示同一结构；碰撞问题见安全考虑。

### 2. 输入

输入是一个 `tapnet/1` 文件：文件头 `"TAPNET" ‖ 0x01 ‖ 0x00 ‖ u32be(nIn) ‖ u32be(nOut)`，后接 TAP-02 记录，只含 NAND 与 LATCH，并按 `TAP-draft-netlist-bound-nft`（§2.2）的定义合法。实现 MUST 拒绝在那里不合法的文件，且 MUST NOT 为它计算结构哈希。特别地，含 REF 记录的文件在本版本中没有结构哈希。

元件 `k` 是 `NAND(a, b)` 或 `LATCH(d)`，信号编号同 TAP-02。输出是信号 `S − nOut … S − 1`；输出 `j` 是信号 `S − nOut + j`。输出信号总是元件信号（TAP-02 §3，条件 3）。

### 3. 活性

**活**元件是满足下列条件的最小集合：包含 `nOut` 个输出元件，并且对每个活元件，包含其输入信号所对应的每个元件（NAND 的 `a` 与 `b`，LATCH 的 `d`）。由于 LATCH 的 `d` 与其它输入一样被追溯，只通过 LATCH 反馈起作用的元件是活的，而没有任何输出读取的环路不是活的。

后续所有步骤只使用活元件。常量和输入不是元件；每个输入编号无论是否被读取都保持其含义。

### 4. 结构标签

**4.1 固定标签。** 信号 0 的标签为 `L(0x00 ‖ u8(0))`；信号 1 的标签为 `L(0x00 ‖ u8(1))`；输入 `i`（信号 `2 + i`）的标签为 `L(0x01 ‖ u32be(i))`。

**4.2 无反馈元件。** **无环**元件集合 `A` 是满足下列条件的最小活元件集合：一个活元件只要其每个属于元件信号的输入都在 `A` 中，它就属于 `A`。（等价地：一个元件属于 `A`，当且仅当从它沿输入向后追溯永远不会进入环路。）`A` 中的每个元件按先标记输入的顺序得到最终标签：

- `NAND(a, b)`：`L(0x02 ‖ min(λa, λb) ‖ max(λa, λb))`；
- `LATCH(d)`：`L(0x03 ‖ λd)`；

其中 `λs` 是信号 `s` 的标签。

**4.3 有反馈元件。** 设 `C` 为不在 `A` 中的活元件（可能为空）。`C` 中每个元件都依赖某个环路，而每个环路都经过一个 LATCH（TAP-02 §3，条件 4 与 5）。`C` 的标签按轮次 `r = 0, 1, 2, …` 计算。在第 `r` 轮，每个信号 `s` 有标签 `λ_r(s)`：常量、输入和 `A` 中元件取其固定或最终标签；`C` 中元件为：

- `C` 中的 LATCH `e = LATCH(d)`：`λ_0(e) = L(0x04)`，且 `λ_{r+1}(e) = L(0x05 ‖ λ_r(d))`；
- `C` 中的 NAND `e = NAND(a, b)`：`λ_r(e) = L(0x02 ‖ min(λ_r(a), λ_r(b)) ‖ max(λ_r(a), λ_r(b)))`。由于 `a` 和 `b` 的信号编号小于 `e`，这一定义是良定的。

设 `n_r` 为 `C` 中各元件 `e` 的 `λ_r(e)` 中不同取值的个数。设 `R` 为满足 `n_r = n_{r−1}` 的最小 `r ≥ 1`。`C` 中每个元件 `e` 的最终标签为 `λ_R(e)`。（`R` 存在，且至多比 `C` 中 LATCH 的个数多一；见设计理由。）实现 MAY 用任何方法计算出相同的标签。

**4.4 最终标签。** 至此每个活元件都有最终标签 `λ(e)`。NAND 标签在 4.2 与 4.3 中都使用标记 `0x02`；标记 `0x03`、`0x04` 与 `0x05` 只用于 LATCH。

### 5. 合并

**节点**是活元件的各个不同最终标签。每个节点 `v` 有一个种类和若干输入标签，取自任一满足 `λ(e) = v` 的活元件 `e`：

- 若 `e = NAND(a, b)`：种类 NAND，输入为 `(min(λa, λb), max(λa, λb))`；
- 若 `e = LATCH(d)`：种类 LATCH，输入为 `λd`。

最终标签相同的所有元件具有相同的种类和相同的输入标签。若实现发现两个元件最终标签相等而种类或输入标签不同，它 MUST 报错停止，而不是给出结构哈希（这只可能由 SHA-256 碰撞引起）。

节点的输入标签是常量、输入或节点的标签。NAND 节点 MAY 有两个相等的输入（例如两个被复制的门合并之后）。

### 6. 规范顺序

**6.1 深度。** LATCH 节点的深度为 0。NAND 节点的深度为 `1 + max(depth(x), depth(y))`，取遍它的两个输入，其中常量、输入或 LATCH 节点按深度 0 计。

**6.2 输出尾部。** 对 `j = 0 … nOut − 1`，令 `o_j = λ(output element j)`（即输出元件 j 的最终标签）；多个输出 MAY 对应同一个节点。令 `first(v)` 为满足 `o_j = v` 的最小 `j`。若 `v` 是 NAND 节点 `w` 的输入标签之一，则称 `w` **读取**节点 `v`。按 `j = nOut − 1, nOut − 2, …, 0` 的顺序处理：节点 `o_j` **放入槽位 `j`**，当且仅当 `first(o_j) = j`，且每个读取 `o_j` 的 NAND 节点都已放入大于 `j` 的槽位。令 `T` 为已放置节点的集合。

**6.3 核心。** 核心是不在 `T` 中的所有节点组成的列表，按二元组 `(depth(v), v)` 升序排列。

**6.4 信号编号。** 常量 0 和 1 是信号 0 和 1；输入 `i` 是信号 `2 + i`；核心中位置 `p`（从 0 起）的节点是信号 `2 + nIn + p`；放入槽位 `j` 的节点是信号 `2 + nIn + |core| + j`。用 `σ(x)` 表示标签为 `x` 的常量、输入或节点的信号编号。

**6.5 记录。** 节点 `v` 的记录为

- 输入为 `(x, y)` 的 NAND：`0x00 ‖ u24(min(σ(x), σ(y))) ‖ u24(max(σ(x), σ(y)))`；
- 输入为 `x` 的 LATCH：`0x01 ‖ u24(σ(x))`。

规范记录依次为：按核心顺序排列的核心节点记录，然后对 `j = 0 … nOut − 1` 给出 `o_j` 的记录。对于放入了节点的槽位，该记录就是节点本身；对于其它槽位，该记录是一条**副本记录**：一个与该节点种类和输入都相同、但不被任何东西引用的第二个元件。

### 7. 规范文件与结构哈希

**规范文件**为

```
"TAPNET" ‖ 0x01 ‖ 0x00 ‖ u32be(nIn) ‖ u32be(nOut) ‖ canonical records
```

其中 `nIn` 与 `nOut` 取自输入文件（代码中 canonical records 即规范记录，canonical file 即规范文件）。**结构哈希**为

```
structuralHash = SHA-256(ASCII("tap-structural-hash/1") ‖ 0x00 ‖ canonical file)
```

在 JSON 中写作 `0x` 后接 64 个小写十六进制数字。

规范文件是一个合法的 `tapnet/1` 文件（见设计理由）。实现 MUST 在返回哈希之前把它当作输入文件（§2）检查一遍；检查失败时 MUST 报告错误而不是哈希（这只可能在副本记录使其超出 TAP-02 的大小限制时发生）。

### 8. 结构哈希保证什么

假设 SHA-256 在相关输入上没有碰撞：

1. **刻画。** 两个合法文件的结构哈希相同，当且仅当它们的 `nIn` 与 `nOut` 相同，且它们合并后的结构（§5 的节点及其种类、输入关系、固定的常量与输入标签，以及有序列表 `o_0 … o_{nOut−1}`）同构。
2. **不变性。** 下列改动的任意组合都不改变结构哈希：以任何保持文件合法的方式重排或重新编号元件，只要输出元件保持其输出顺序；交换任一 NAND 的两个输入；增加、删除或修改非活元件；把一个元件替换为若干种类与输入都相同的元件（复制），并把它的读取方（包括 LATCH 反馈）分配到这些副本上；以及把这样的副本重新合并。
3. **行为。** 从全零状态出发，对每个输入序列，规范文件计算出的输出序列与输入文件相同（TAP-02 §4）。它的状态布局、`nState` 和门数一般与输入文件不同。
4. **幂等。** 规范文件的规范文件就是它自身，因此两者结构哈希相同。

下列改动会改变结构哈希：输入或输出的置换（除非该置换把结构映射到自身，例如交换对称 XOR 的两个输入）；`nIn` 或 `nOut` 的改变，包括增加一个不用的输入；插入或去掉诸如用 `NAND(NAND(x, x), NAND(x, x))` 代替 `x` 这样的逻辑；常量化简，例如用 `NAND(x, 1)` 代替 `NAND(x, x)`；德摩根改写、LATCH 重定时，以及其它任何保持函数而改变结构的改动。

### 9. 集合与工具的使用

1. 集合、交易市场或稀有度工具在陈述一组网表包含多少个不同设计时，MUST 统计不同结构哈希的个数，并且 SHOULD 在旁边给出网表哈希的个数。
2. 携带结构哈希的元数据 SHOULD 把它以 `"structuralHash"` 放在 `TAP-draft-netlist-bound-nft` 中 `tap` 对象的 `netlist` 成员里，与 `sha256` 并列（对按该草案 §2.5 定义的格式的网表，则与取代 `sha256` 的成员并列），写作 `0x` + 64 个小写十六进制数字。该草案对本 TAP 为之定义了结构哈希的格式与文件定义这个成员（§7.1）：有效的 `tapnet/1` 文件（§2），以及在第 2 版中，不含 §10 未定义记录的有效 `tapnet/2` 文件（§10.1）。
3. 工具 MUST NOT 把结构哈希不同的两份网表描述为函数不同，也 MUST NOT 把结构哈希相同的两份网表描述为指标（门数、`nState`）相同：哈希只标识结构。
4. 为不可信文件计算结构哈希的工具 MUST 在计算前限制记录数（TAP-02 §7，要求 1）；开销见安全考虑。
5. 实现 MUST 在分配按记录的数据结构之前完成 §2 的文件检查（TAP-02 §7，要求 2）。
6. 改变任何步骤的后续版本 MUST 使用不同于 `tap-structural-hash/1` 的域标签，以及不同于 `TAPSH1` 的标签前缀，除非它是保守扩展：它不改变每个具有第 1 版结构哈希的输入的规范文件和结构哈希，只为新的记录种类增加新的标签标记，让含有它未定义的记录的每个文件都没有结构哈希，并对含有新记录种类的规范文件使用新的域标签。第 2 版（`tap-structural-hash/2`，§10）就是这样的扩展。

### 10. 第 2 版：`tapnet/2` 文件

本节为 `TAP-draft-large-netlists` §1 的 `tapnet/2` 格式（ROM 记录 `0x10`、RAM 读口 `0x11`、RAM 写口 `0x12`、ROM 读口 `0x13`、标志字节）定义 `tap-structural-hash/2`。§2–§8 中本节未提及的步骤原样适用。`u16be(x)` 表示把 `x` 写成 2 字节无符号大端整数，同 `TAP-draft-large-netlists` §0。

**10.1 适用范围。** 第 2 版对每个合法的 `tapnet/1` 文件（§2）和每个合法的 `tapnet/2` 文件（`TAP-draft-large-netlists` §1.2）有定义。它是第 1 版的保守扩展：对合并后结构（10.7）中既没有 ROM 节点也没有 RAM 节点的每个输入（包括每个 `tapnet/1` 文件），规范文件和结构哈希与 §2–§7 的结果逐字节相同。含有本节未定义的记录（例如以后的格式新增的记录种类）的文件在第 2 版中没有结构哈希；实现 MUST 拒绝它，并且 MUST NOT 把该记录当作另一种记录来解释。

**10.2 元件与位平面。** 在 `tapnet/2` 文件中：

- 每条 NAND 和 LATCH 记录是一个元件；
- 一条有 `w` 个输出位的 ROM 记录是 `w` 个元件，每个输出位一个：**ROM 列** `j`（`0 ≤ j < w`）产生信号 `first + j`，其中 `first` 是该记录产生的第一个信号；它的输入是记录的 `a` 个地址引用（`addr[0]` 为最低位），它的表是 `2^a` 位 `T[m]` = 记录数据的流位 `m·w + j`；
- ROM 读口同样是 `w` 个 ROM 列，使用它自己的地址引用和位于 `romOffset` 的 ROM 记录的数据（它与其它 ROM 列没有区别；间接引用不属于结构）；
- 存储体 `b` 的一个有 `w` 个输出位的 RAM 读口是 `w` 个元件：**RAM 读列** `j` 产生信号 `first + j`，读取该存储体的第 `j` 位；
- RAM 写口不产生信号，也不是元件。

对每个宽度为 `w` 的存储体 `b` 和每个 `j < w`，**位平面** `(b, j)` 是存储体 `b` 所有条目的第 `j` 位：一个有 `2^a` 个一位条目的存储器，只有 `b` 的第 `j` 读列读取它，`b` 的每个写口以其 `we`、地址和 `wdata[j]` 写它。（参考性说明：条目的第 `j` 位独立于其它位演化，所以 `w` 位宽的存储体就是共享地址与使能接线的 `w` 个一位存储器，正如 `w` 位宽的 ROM 是 `w` 列。）位平面不是信号；它们是存储器的状态元件，正如 LATCH 是单个位的状态元件。

**10.3 活性。** §3 按以下规则适用：活的 ROM 列使其地址引用中的元件成为活的；活的 RAM 读列使其地址引用中的元件成为活的，并使其位平面成为活的；活的位平面 `(b, j)` 对存储体 `b` 的每个 `we` 不是信号 0 的写口，使其 `we`、地址引用和 `wdata[j]` 中的元件成为活的。同一记录的其它列、同一存储体的其它位平面、以及 `we` 为信号 0 的写口不因此成为活的。没有任何活读列读取的位平面不是活的，它的写也不是。

**10.4 ROM 列。** 给定其输入的标签 `λ`，输入为 `p_0 … p_{a−1}`、表为 `T` 的 ROM 列的**约简形式**是：

1. 令 `q_0 < q_1 < … < q_{k−1}` 为 `λ(p_i)` 中不等于 `L(0x00 ‖ u8(0))` 或 `L(0x00 ‖ u8(1))` 的不同标签，按升序排列（`0 ≤ k ≤ a`）。
2. 对 `0 ≤ m < 2^k`，令 `addr(m) = Σ_i b_i · 2^i`，其中若 `λ(p_i) = L(0x00 ‖ u8(0))` 则 `b_i = 0`，若 `λ(p_i) = L(0x00 ‖ u8(1))` 则 `b_i = 1`，否则 `b_i` 是 `m` 的第 `r` 位（`r` 满足 `q_r = λ(p_i)`）。约简表为 `t[m] = T[addr(m)]`。
3. `tbytes` 是 `t` 按 LSB 优先打包（位 `m` 是字节 `⌊m/8⌋` 的第 `m mod 8` 位）成的 `⌈2^k / 8⌉` 个字节，未用的高位为零（`k = 0` 时为一个字节）。

ROM 列的标签是 `L(0x06 ‖ u8(k) ‖ q_0 ‖ … ‖ q_{k−1} ‖ tbytes)`。（参考性说明：接在信号 0 或 1 上的地址引用被折叠进表；标签相同的引用被合并到表的对角线；其余引脚按标签排序，表随之置换。约简从不根据表的内容决定保留哪些引脚。）

**10.5 RAM 位平面。** 对地址宽度为 `a` 的存储体的一个活位平面 `P = (b, j)`，`P` 的**端口**是它的活读列，以及存储体 `b` 中 `we` 不是信号 0 的写口。若 `P` 的每个端口都以同一个常量信号（0 或 1）作为 `addr[i]`，则地址位置 `i` 在 `P` 中是**固定的**；其余位置按升序是 `P` 的**保留**位置 `i_0 < … < i_{k−1}`（`0 ≤ k ≤ a`）。保留位置只由信号编号和活性决定，在计算任何标签之前确定。

给定标签 `λ`，`P` 的**写列表**按如下方式得到：存储体 `b` 中 `we` 不是信号 0 的写口按文件顺序各贡献一个元组 `λ(we) ‖ λ(addr[i_0]) ‖ … ‖ λ(addr[i_{k−1}]) ‖ λ(wdata[j])`（`k + 2` 个标签）；然后删除每个与列表中某个更靠后的元组相等的元组，其余元组保持顺序。位平面为 `P` 的 RAM 读列的**输入**是 `addr[i_0] … addr[i_{k−1}]`（它在 `P` 的保留位置上的引用）。

**10.6 标签。** §4.2 的依赖关系扩展为：ROM 列依赖其输入；RAM 读列依赖其输入和其位平面；位平面依赖其存储体中每个 `we` 不是信号 0 的写口的 `we`、保留位置上的引用和 `wdata[j]`。一个位平面或元件属于 `A`，当且仅当从它沿这些依赖向后追溯永远不会进入环路。`A` 中的标签：

- ROM 列：由其输入的最终标签按 10.4 计算；
- 有 `k` 个保留位置的位平面 `P`：`L(0x07 ‖ u8(k) ‖ 写列表)`，写列表（10.5）写成其各元组的串接；
- 位平面为 `P`、输入为 `x_0 … x_{k−1}` 的 RAM 读列：`L(0x0A ‖ λ(P) ‖ λ(x_0) ‖ … ‖ λ(x_{k−1}))`。

在 §4.3 中，不在 `A` 中的位平面像 LATCH 一样细化，不在 `A` 中的 ROM 列与 RAM 读列像 NAND 一样计算：`C` 中有 `k` 个保留位置的位平面 `P` 取 `λ_0(P) = L(0x08 ‖ u8(k))`，`λ_{r+1}(P) = L(0x09 ‖ u8(k) ‖ 由第 r 轮标签计算的写列表)`；`C` 中的 ROM 列或 RAM 读列的 `λ_r` 是由第 `r` 轮标签（其输入的，以及读列的位平面的）按上式计算的标签；这是良定义的，因为地址引用的信号编号小于该列。`n_r` 统计 `C` 中元件 `e` 的 `λ_r(e)` 与 `C` 中位平面 `P` 的 `λ_r(P)` 合在一起的不同值个数；`R` 的定义不变。

**10.7 合并。** 在 §5 中，元件为 ROM 列的节点种类为 ROM，输入标签为 `q_0 … q_{k−1}`（按此顺序），约简表为 `t`；元件为 RAM 读列的节点种类为 RAM，带有其位平面的标签和输入标签 `λ(x_0) … λ(x_{k−1})`（按此顺序）。最终标签相同的位平面构成一个**位平面节点**，带有其保留位置数 `k` 和写列表。最终标签相同的所有元件（或位平面）具有相同的种类，以及相同的输入标签、约简表、位平面标签或写列表；否则实现 MUST 报错停止。`k = 0` 的 ROM 节点是**常量列**；它是一个节点，与常量（信号 0 和 1）不同。RAM 节点从不与常量合并，即使其位平面的写列表为空。

**10.8 规范顺序。** 在 §6.1 中，ROM 或 RAM 节点的深度为其输入标签深度的 `1 + max`（没有输入时为 `1`），常量、输入和 LATCH 节点按深度 0 计；位平面节点没有深度，不属于核心。在 §6.2 中，"NAND 节点 `w` 读取节点 `v`"改为"NAND、ROM 或 RAM 节点 `w` 读取节点 `v`"，ROM 或 RAM 节点读取其输入标签。位平面节点按标签升序编号为 `0, 1, …`；这个编号就是它在规范文件中的**存储体**号。若位平面节点超过 256 个，实现 MUST 报错而不是给出哈希。

**10.9 记录。** 在 §6.5 中：

- 位平面存储体号为 `β`、输入为 `(x_0 … x_{k−1})` 的 RAM 节点的记录为 `0x11 ‖ u8(β) ‖ u8(max(k, 1)) ‖ u16be(1) ‖ u24(σ(x_0)) ‖ … ‖ u24(σ(x_{k−1}))`，`k = 0` 时为单个引用 `u24(0)`；
- 输入为 `q_0 … q_{k−1}`、约简表为 `t` 的 ROM 节点的记录：`k ≥ 1` 时为 `0x10 ‖ u8(k) ‖ u16be(1) ‖ u24(σ(q_0)) ‖ … ‖ u24(σ(q_{k−1})) ‖ tbytes`，`k = 0` 时为 `0x10 ‖ u8(1) ‖ u16be(1) ‖ u24(0) ‖ u8(3·t[0])`（一个接在信号 0 上的地址位，表为 `[t[0], t[0]]`）。若规范记录中更早已有一条地址宽度相同、数据字节相同的 ROM 记录（`0x10`），则该记录改写为 ROM 读口 `0x13 ‖ u32be(o) ‖ u8(a) ‖ u16be(1) ‖（相同的地址引用）`，其中 `o` 是第一条这样的 ROM 记录在规范文件中的字节偏移，`a` 是它的地址宽度。

ROM 与 RAM 节点的副本记录也是这种形式的记录。规范记录是 §6.5 的核心记录和输出槽记录，后接**写记录**：按存储体号顺序对每个位平面节点，按顺序对其写列表中的每个元组 `(we, y_0 … y_{k−1}, d)`，写 `0x12 ‖ u8(β) ‖ u8(max(k, 1)) ‖ u16be(1) ‖ u24(σ(we)) ‖ u24(σ(y_0)) ‖ … ‖ u24(σ(y_{k−1})) ‖ u24(σ(d))`，`k = 0` 时地址为单个引用 `u24(0)`。（写记录不产生信号，所以输出仍是最后 `nOut` 个信号。）

**10.10 规范文件与哈希。** 若既没有 ROM 节点也没有 RAM 节点，规范文件和结构哈希就是 §7 的结果（`tapnet/1` 文件，域 `tap-structural-hash/1`）。否则规范文件为

```
"TAPNET" ‖ 0x02 ‖ u8(flags) ‖ u32be(nIn) ‖ u32be(nOut) ‖ 规范记录
```

其中至少有一个位平面节点时 `flags = 0x01`，否则为 `0x00`；并且

```
structuralHash = SHA-256(ASCII("tap-structural-hash/2") ‖ 0x00 ‖ 规范文件)
```

实现 MUST 把这个规范文件当作 `tapnet/2` 文件检查（`TAP-draft-large-netlists` §1.2），检查失败时 MUST 报错而不是给出哈希（只可能发生在逐列记录、写记录或副本记录使其超过 64 MiB 或 2^24 个信号的上限时）。结构哈希对文件字节用 SHA-256 计算，而不是用 `netlistHash2`。

**10.11 保证。** §8 对 10.7 的合并后结构成立：两个 ROM 节点对应，当且仅当约简表相同且输入标签对应；两个 RAM 节点对应，当且仅当其位平面和输入对应；两个位平面节点对应，当且仅当 `k` 相同且写列表对应；行为（§8 第 3 项）是从全零状态和全零存储器起算（`TAP-draft-large-netlists` §1.3）。除 §8 第 2 项的不变性之外，结构哈希在下列变换下不变：

- ROM：置换 ROM 的地址引用并相应置换其表；置换、增加或删除没有被读取的输出位；把一个 ROM 拆成地址引用相同的几个 ROM，或把这样的 ROM 合并；复制 ROM 或其部分列并分配读者；增加接在信号 0 或 1 上的地址引用（另一取值上的表项任意）；把已是地址引用的信号再接到第二个地址引用上（对角线以外的表项任意）；
- ROM 读口：把 ROM 读口换成持有一份表副本的 ROM 记录，或反过来；
- RAM：存储体重新编号；在存储体的所有端口中一致地置换其位（每个写口的 `wdata` 与每个读口的列，读者随之重接）；用没有活读列读取的位加宽存储体；按位把一个存储体拆成几个存储体（每个端口都复制一份），或把这样的存储体合并；复制读口并分配读者；把写口紧接着复制一份（更一般地，增加一个与同一存储体中更靠后的写口相同的写口）；增加 `we` 为信号 0 的写口；增加没有活读列依赖的存储体、读口或写口；增加一个在该存储体所有活端口中都接同一常量的地址位；以任何合法方式重排记录，只要每个存储体的写口相对顺序不变；
- 格式：在没有 ROM 或 RAM 节点剩下时（例如 ROM 与 RAM 端口全都没有被读取的 `tapnet/2` 文件）在 `tapnet/1` 与 `tapnet/2` 之间转换。

结构哈希在下列变换下改变：用 NAND 逻辑代替 ROM（包括 `TAP-draft-large-netlists` §1.3 的展开）或反过来；把 ROM 列当作缓冲器、反相器或 NAND 使用；增加表不依赖的地址引用；按地址把 ROM 拆成较小的 ROM 加多路选择器；改变任何表项，包括没有可达状态会寻址到的表项；用 LATCH 与多路选择器代替 RAM 或反过来；交换同一存储体的两个不同写口；增加一个可能被使能的写口，即使它总被后面的写覆盖；置换存储体的地址位；除"在所有活端口中接同一常量的地址位"以外改变存储体的地址宽度；把两个存储体放进同一个存储体的不同地址区域。从未被写过的存储体的 RAM 读列每一拍都读到 0，但它不是常量 0：读取它的 NAND 与读取信号 0 的 NAND 标签不同。

## 设计理由

**与 TAP-721 的关系。** 本 TAP 是单独的 Standards 类 TAP，而不是 TAP-721 的一节，因为它规定的是一个可能演进的算法：例如以后的版本可能在新的域标签下加入常量传播（§9 第 6 条），这样的改动既不应导致 TAP-721 重新修订，也不应触及网表哈希——网表哈希始终是 TAP-721 代币的字节级身份。分开之后，TAP-721 可以独立推进，结构哈希则可以积累独立实现，只核验 TAP-721 代币的工具也无需实现它。它仍属 Standards 类，因为各个独立实现必须逐字节一致（见下文）。

**是结构，而不是函数。** 集合要回答的问题是"这两个代币是同一个设计吗？"，而不是"这两个电路算的是同一个东西吗？"。XOR 的两种不同实现（4 个 NAND 和 5 个 NAND）是不同的设计，成本不同，作者也不同；向量 `xor_17851` 与 `xor_5nand` 的哈希不同是有意为之。设计证明（PoD）挖矿做了同样的选择：它对每个注册的设计分别评分，并按设计成本给同一题目的设计排名，所以一个函数层面的标识符恰好会合并 PoD 要区分开的东西。

**为什么不用 SAT 或 BDD 等价判定。** 组合等价检查是 coNP 完全的，时序等价（带 LATCH 状态）是 PSPACE 完全的；BDD 在乘法器上会爆炸。哈希必须能被任何人在接近线性的时间内算出，没有超时、没有求解器版本、没有"未判定"的结果；否则两个工具会对同一对网表给出不同结论。等价判定也给不出规范名字：知道 A 等于 B，并不能得到一个可以拿来与第三份网表 C 比较的值。

**与 PoD 最优首创规则的关系。** PoD 比较同一题目不同提交的设计成本 `C = A·max(d,1)^β`，青睐最便宜的；它从不追问两份提交是否是同一个设计。结构哈希回答的正是后一个问题。两者互补：集合可以同时展示"有多好"（PoD 属性）和"有多少个不同的"（结构哈希）。

**合并，而不是打破平局。** 图的规范化一般很难，因为有些节点无法通过局部细化区分开；这些节点需要任意的打破平局规则，结果也就不再不变。本 TAP 通过合并细化无法分开的每一对元件来回避这个问题。§4 的最终标签相等，恰好对应元件*互模拟*：种类相同，输入两两互模拟（NAND 按无序对），常量和输入只与自身相等。从全零状态起，互模拟的元件在每一拍都承载相同的值（对拍数归纳：LATCH 从 0 开始，相同的输入给出相同的输出），所以合并它们保持行为。合并之后，任意两个节点都不互模拟；合并后结构的一个自同构本身就是一个互模拟，所以合并后的结构没有非平凡自同构，每个节点的标签都不同，§6 的规范顺序是全序。不存在后备的打破平局规则，因为不需要。这给出了 §8 的刻画：规范文件是合并后结构的同构类的函数，而合并后的结构又能从规范文件中读回。

**合并覆盖的不只是副本。** 互模拟也会合并那些不是字面副本、但出于结构原因行为相同的元件：由同一输入驱动的两个独立翻转器（`two_toggles`），或者一个保持自身的 LATCH 与两个互相保持的 LATCH 组成的环（两者恒为 0；`const_ring_1` 与 `const_ring_2` 哈希相同）。这些合并是可靠的，只依赖结构，不考察常量。

**为什么按展开深度打标签，为什么分成 `A` 与 `C`。** 4.2 的标签是元件完整后向锥的哈希，只计算一次。有反馈的元件后向展开是无限的，所以它们的标签是截断在 `r` 步 LATCH 处的展开的哈希；轮次标签单调细化（`λ_{r+1}` 相等蕴含 `λ_r` 相等），所以类的划分只会分裂；一旦某一轮没有分裂任何类，划分就永远稳定，因为第 `r + 1` 轮只依赖第 `r` 轮。每个没有停止的轮次至少分裂一个 LATCH 类，这给出了 `R` 的上界。展开有限的元件永远不会与展开无限的元件互模拟，所以单独处理 `A` 与对全部元件跑轮次得到相同的合并，同时让长移位寄存器和其它无反馈结构保持线性。LATCH 的轮次标签不包含它自己上一轮的标签；没有它，单调性也成立。

**为什么按 `(depth, label)` 排序。** LATCH 节点深度为 0，排在最前；NAND 节点的输入深度更小；所以核心中的每个 NAND 都向后引用，而 LATCH 记录可以引用任何位置（TAP-02 §3，条件 5）。深度优先使规范文件可读（分层），标签用来打破平局。

**为什么需要输出尾部和副本记录。** `tapnet/1` 规定输出是按顺序的最后 `nOut` 条记录。合并之后，两个输出可能是同一个节点，而一个输出节点也可能被一个必须排在更后面的 NAND 读取。6.2 的规则在有效时把节点留在它的输出槽位，否则把它留在核心中，并在槽位里写一条副本记录。有效性：放在尾部的 NAND 只读取核心节点或放在更早槽位的节点（放在槽位 `s` 的节点只被放在更晚槽位的 NAND 读取）；核心中某节点的副本记录只读取核心节点；对于放在槽位 `first(v) < j` 的节点，它在槽位 `j` 的副本只读取放在 `first(v)` 之前的节点。副本记录不被任何东西读取，所以对规范文件再做规范化会把每个副本并回其节点，并重现同样的放置（幂等）。因此规范文件最多可比合并后的结构多 `nOut` 条记录，甚至可能比输入文件还大；元数据中的指标始终取自输入文件。

**为什么第 1 版不做常量传播。** 用 `NOT x` 代替 `NAND(x, 1)`、用 1 代替 `NAND(x, 0)`，是逻辑优化的第一步；一旦开了这个口子，就没有一个有原则的停止点（双重否定、吸收律、德摩根、重定时），而每多一条规则都会改变所有哈希。输出也可能变成常量，而 `tapnet/1` 无法表达这种情况，因为输出必须是元件。常量对 PoD 成本也有影响，PoD 按写出的门计数。因此第 1 版把常量当作两个固定的叶子。同理，`NAND(NAND(x, x), NAND(x, x))` 不化简为 `x`（`not_twice` 与 `not_four_times` 不同）。

**为什么输入和输出保持顺序。** 有序的引脚是设计的接口；交换了两个输入的元件，接入更大的电路时就是另一个元件。交换输入只有在结构对称时才得到相同的哈希（`xor_inputs_exchanged`），否则哈希不同（`andnot`、`andnot_inputs_exchanged`）。

**为什么要规范文件而不只是哈希。** 规范文件本身就是一份合法、可运行的网表；任何人都可以查看它、运行它，并从它重新计算哈希。用域标签对它做哈希，使结构哈希与相同字节的网表哈希区分开。

**为什么是 Standards 而不是 Application。** 两个以不同方式统计设计的工具会对同一个集合得出不同结论，这是互操作性失败，而不是约定问题；因此规范文件和哈希必须由各个独立实现逐字节复现，并配有向量。

**为什么排除 REF。** REF 的结构存在于另一个电路中，并且取决于某个区块时的处理器（TAP-02，安全考虑）。展平规则留给后续版本定义（待定问题）。

**第 2 版：ROM 与 RAM 作为节点（§10）。**

- *ROM 作为节点。* 把 ROM 展开成 NAND 会让哈希依赖一个参考性的展开：它按地址位顺序嵌套多路选择器（因此对地址置换不是不变的），会折叠常量（而第 1 版对 NAND 拒绝这样做），对大 ROM 还会超过 2^24 个信号。掩膜 ROM 与 NAND 多路选择器是不同的设计，正如 XOR 的两种 NAND 实现是不同的设计。
- *每个 ROM 列、每个 RAM 位一个节点。* 每个 ROM 列和每个 RAM 读列只产生一个信号，于是 §5 和 §6 原样适用；死位、列顺序、拆分以及重复的 ROM 或端口都由活性和合并处理，不需要额外规则。以整个存储体或整个读口为节点的方案被否决：读口产生 `w` 个连续信号，作为输出的其中一位无法放进单信号的输出槽位，也无法用副本记录复制，而 §8 第 4 项又排除了插入缓冲器。规范文件把每个位平面写成宽度为 1 的存储体，把每个活读位写成单独的读口；代价是每列、每个写元组多一个头部。
- *位平面是状态，读列是组合逻辑。* 读口返回本拍开始时的存储器内容，正如 LATCH 返回其状态，但其地址在同一拍起作用。因此位平面像 LATCH 一样细化（第 0 轮标签只取决于 `k`），读列像 NAND 一样计算。最终标签相同的两个位平面从全零存储器起每一拍内容都相同（与 LATCH 一样对拍数归纳），所以合并它们保持行为。
- *写顺序是结构。* 同一拍有多个写口写同一条目时，文件中最后一个生效（`TAP-draft-large-netlists` §1.3），所以写列表保持文件顺序，交换两个不同的写口会改变哈希。删除与更靠后元组相等的元组是可靠的：更靠后的端口在同一使能下、在它之后向同一条目写同一个值，而读只看到本拍开始时的存储器。这一步也只由标签驱动并且单调：若两个位平面第 `r+1` 轮标签相等，它们约简后的第 `r` 轮写列表相等；第 `r−1` 轮标签是更粗的划分，删除在更粗划分下变得相等的元组与已做的删除可交换，所以第 `r` 轮标签相等，第 1 版关于 `R` 的论证成立（位平面与 LATCH 一样计数）。总被后续端口覆盖但数据不同的写口不删除：那是优化，而且它的数据锥按 §10.3 是活的，其中可能含有反馈，会改变 `R` 从而改变 `C` 的每个标签（与下面 ROM 的 don't-care 引脚是同一障碍）。
- *存储器的静态规则。* `we` 接在信号 0 上的写口，以及位平面所有活端口都接同一常量的地址位，只靠信号编号和活性识别，在标签存在之前确定，因而不会与细化相互作用。折叠这样的地址位是安全的，因为没有端口能寻址位平面的另一半。有两件事不做：置换存储体的地址位（规范的位顺序必须对位平面的所有端口联合选取，对称位之间需要打破平局）；在"每个端口都是常量但取值不同"的位上把位平面拆成区域（需要一条知道哪些写能到达哪些读的活性规则）。两者都列为待定问题。
- *ROM 读口。* ROM 读口是表的第二个读者。把它的列当作 ROM 列，使"通过端口共享表"的文件与"持有表副本"的文件哈希相同（`romports` 与 `romdup`）。规范文件对每个不同的约简表只存一次，其余通过 ROM 读口读取，这样一个依靠端口才能放进 64 MiB 的设计，其规范文件也放得下。
- *只做标签驱动的 ROM 引脚约简。* 折叠常量引脚、合并标签相同的引脚只依赖输入标签，从不依赖表的内容；合并本来就是必需的，因为按标签排序在相同标签之间没有规范的次序。删除表不依赖的引脚，或把全相同的列换成常量信号，属于逻辑优化，没有原则性的停点；它还会让按原始引用为活的元件实际上成为死的，挂在这类引脚后的死反馈环会改变 `R`，从而改变 `C` 的每个标签；而且两种格式都无法写出常量输出。
- *ROM 列的单调性。* 若两个 ROM 列第 `r+1` 轮标签相等，则它们的约简形式相等；对应输入在第 `r` 轮标签相等，第 `r` 轮约简形式由第 `r+1` 轮约简形式经过同样的进一步合并和重排得到，所以第 `r` 轮标签相等。`C` 中的 ROM 列或 RAM 读列至少保留一个在 `C` 中的输入或位平面，所以其标签不会等于 `A`、常量或输入的标签；`C` 中的位平面标签使用专用的标记。
- *幂等。* 规范文件具有合并后的结构：位平面节点成为宽度为 1 的存储体，其写记录恰好列出写列表，没有使能为信号 0 的写口，除 `k = 0` 时的那个填充位外也没有固定地址位，而该填充位在该存储体的所有端口中都接信号 0，会被再次折叠；通过 ROM 读口共享的表被读回为同样的列；副本记录与第 1 版一样被并回。
- *存储体数上限。* `tapnet/2` 用一个字节给存储体编号，所以规范文件最多容纳 256 个位平面节点。不同 RAM 位更多的设计得到错误而不是哈希。按地址区域把几个位平面装进一个存储体可以解除上限，但需要上面的区域拆分；列为待定问题。
- *成本。* 给 ROM 列打标签的成本为 `O(k · 2^k)`；在 `C` 中每轮都要重做，因为输入的标签顺序会变。位平面每轮扫一遍其写元组，从不涉及 `2^a`。这与第 1 版 `O(R·|C|)` 的成本同形。服务可以按 `netlistHash2` 缓存结构哈希。
- *保守扩展。* 格式版本是表示细节；一个设计从 `tapnet/1` 迁到 `tapnet/2`，只要没有 ROM 或 RAM 节点，就保留其结构哈希。标签仍用前缀 `TAPSH1`；标记 `0x06`–`0x0A` 是新的，所以已有标签都不变。含有第 2 版未定义的记录种类的文件不得到哈希，而不是得到一个猜测的哈希。

## 向后兼容

本 TAP 增加一个标识符，不改变任何已有内容。`TAP-draft-netlist-bound-nft` 中的网表哈希、版次和指标不受影响。

本草案依赖 TAP-721（`TAP-draft-netlist-bound-nft`），并在其之后提交。TAP-721 是核心草案申请的编号；若编辑分配了其它编号，本草案即采用该编号：本文中对 `TAP-draft-netlist-bound-nft` 和"TAP-721"的所有引用（包括 `requires` 字段）都替换为该编号。

第 2 版（§10）依赖 `TAP-draft-large-netlists` 的 `tapnet/2` 格式。它增加第二个域标签和新的标签标记，不改变任何第 1 版的规范文件或哈希：第 2 版实现复现第 1 版的每个测试向量，无论以 `tapnet/1` 输入还是改头为 `tapnet/2` 输入。若 `TAP-draft-large-netlists` 获得编号，本文中对它的所有引用（包括 `requires` 字段）都替换为该编号。

## 安全考虑

- **不是函数标识符。** 结构哈希不同并不意味着行为不同，这个哈希也不能证明一个集合的设计在函数上互不相同。结构哈希相同则确实意味着从全零状态起行为完全相同（§8）。
- **刻意制造变体很便宜。** 任何人都可以在不改变函数的情况下改变结构哈希，例如插入双重否定、用德摩根改写一个门，或增加一个不用的输入。这个哈希去掉的是零成本改写（重新编号、交换、死门、副本），仅此而已。声称设计稀缺的集合仍须说明其设计是如何产生的；读者应把结构哈希计数看作设计数的上界，而不是原创性的度量。
- **碰撞。** 标签和结构哈希依赖 SHA-256 的抗碰撞性。标签之间的碰撞在会导致不一致合并的地方被检测出来（§5）；构造两个完整规范文件之间的碰撞需要一次 SHA-256 碰撞。
- **对抗性输入的开销。** 活性、`A` 的标签、合并和尾部都与记录数呈线性；核心排序为 `O(n log n)`。`C` 的细化每轮遍历一次 `C`，而 `R` 至多为 `C` 中 LATCH 数加一，所以最坏情况是反馈区域大小的平方。最坏情况由一个长环达到，环中的 LATCH 只能靠它们与单个抽头的距离区分。用参考实现*实测*（CPython 3.9，单核）：一个 2,000 个 LATCH 的环需要 2,000 轮、3.2 秒，一个 50,000 级的移位寄存器（无反馈）需要 0 轮、0.95 秒。能放进一笔 BNB Smart Chain 交易的网表远小于平方项对原生代码产生影响的规模，但工具必须在计算前限制不可信文件的记录数（§9 第 4 条）；服务可以按网表哈希缓存结构哈希，因为结构哈希是文件的函数。
- **内存。** 解码只在 §2 的文件检查之后进行（§9 第 5 条），所以格式错误的文件无法让工具按它自称的长度成比例地分配内存。
- **接口把戏。** 由于输入和输出的顺序是哈希的一部分，集合可以把一个设计的引脚置换后当作多个设计展示。关心这一点的工具还可以在它们认为等价的引脚置换下比较网表的结构哈希；本 TAP 不定义与引脚顺序无关的哈希（待定问题）。

### 待定问题

1. 后续版本是否应以反馈区域的拟线性规范标记（例如 Hopcroft 或 Paige–Tarjan 风格的划分细化，它在 `O(n log n)` 内找到相同的类，再结合对类的规范命名）取代 §4.3 的轮次。
2. REF 电路的展平规则，使带子电路的网表也能有结构哈希；以及它应属于本 TAP 还是以后的某种格式。
3. 考虑到需要在对称引脚之间打破平局，稀有度工具是否需要第二种与引脚顺序无关的哈希（在输入和输出置换下规范）。
4. 是否应把一小组固定的可靠化简（例如 NAND 的常量输入）作为一个单独、明确命名的哈希提供，而不是改变本哈希。
5. 在 `C` 中按字典序历史 `(λ_0, …, λ_r)` 给 ROM 输入排序：两个输入一旦区分开，次序就不再变化，可把 ROM 列每轮的成本从 `O(k·2^k)` 降到 `O(k)`，代价是要跨轮维护秩。
6. 在规范文件中把位平面装进更少的存储体（按地址区域，并配合一条在"每个端口都接常量"的地址位上拆分位平面的规则），以解除 256 个位平面节点的上限；以及把输入相同的 ROM 列重新组合成更宽的 ROM 记录。
7. 存储体范围的地址位置换是否应成为不变性——它需要对一个位平面所有端口的地址位联合选取规范顺序。
