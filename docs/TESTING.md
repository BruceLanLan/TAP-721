## Requirements

- Python 3.9+ supported; 3.11.15 was the runtime for the recorded runs above. Only the PoD tools need a third-party package:
  `pip install pycryptodome` (keccak-256). `tools/collection` imports it lazily, only for `--pod-snapshot`,
  which `test_pipeline.py` uses.
- Foundry v1.8.3 (`forge`, `cast`, `anvil`). `test_pod.py` cross-checks trait keys with `cast keccak` when
  `cast` is on `PATH`; `test_e2e.py` needs `anvil` and `forge`.
- Node 20+ for the gateway (no npm dependencies).
- Submodule: `git submodule update --init` (forge-std v1.17.0).

## Suite details

### 1–4 Python reference implementations

Each `test_*.py` regenerates its vectors and compares them byte for byte with the committed files, then
re-verifies every vector and runs property tests with a fixed RNG seed (bijection of the permutation, Merkle
round trips; for D, invariance under renumbering, input swaps, dead and duplicated elements). Details:
the README in each asset folder.

### 7 Fork test

Runs against X Layer mainnet state without broadcasting. Needs `--evm-version cancun` because the X Layer site
store uses Cancun opcodes while this project compiles for Shanghai.

### 10 Collection pipeline

Builds the collection in set mode in a temporary directory (7,000 revealed tokens out of ids 1–10,000, the
other 3,000 served as excluded placeholders), fetches a real past drand quicknet round (33,145,012), reveals,
serves the output over a local HTTP server and verifies it, then checks that tampering is detected. The current
`test_pipeline.py` has 8 tests, one more than the recorded 7-test run, and has not been re-run inside this
repository since; the introductory article (`docs/article/tap-721.md`) reports 8/8 from the final run in the
working folder. It is heavy (≈ 9,999 HTTP fetches, ≈ 33 MB of metadata). Observed once: when run in parallel with
suite 11 on the same machine, the local HTTP verification hit a socket timeout (`Errno 60`) and failed;
run alone it passes. Set `TCT1_TEST_OUT` to keep the output.

### 11 Uploader end-to-end

Starts `anvil --fork-url https://rpc.xlayer.tech --hardfork cancun`, impersonates the holder of
`1.2.282.tape`, uploads, verifies, and runs the lock checklist with a `TapContainerLock` deployed on the fork.
Sends nothing to a live chain; generates a random throw-away key.

## Notes on the synced sources

- `tools/tokenset/` (owner scan of TapeCode-Test1 at a pinned block, token-set builder) has no test suite; its
  output `tokens.json` is the source of `contracts/test/fixtures/core-tokenset.json`.
- The inconsistencies reported after the first import (stale bridging vectors hash in the asset README, `/1`
  vs `/2` vector format in the Chinese bridging draft, an absolute local path in the profile) are fixed at the
  source.
- `docs/DESIGN.md` is rewritten by the sync script so that repository paths resolve from `docs/`.
- The fairness and economics review is withheld (see [SECURITY.md](SECURITY.md)); `DESIGN.md` §0 states only
  its qualitative finding (some PoD-verified miners compute the wrong function), without circuit ids or counts.
- Bridging (extension B) is tested only with mock endpoints and adapters (`contracts/test/bridge/`,
  `AuditBridge.t.sol`) and the payload vectors (suite 4); nothing has been run over real LayerZero V2 or TAP-10
  hub messages.
